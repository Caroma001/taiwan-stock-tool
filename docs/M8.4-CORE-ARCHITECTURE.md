# twstock-M8.4 Core Engine

## Development default

M8.4 uses a fail-closed safety model. Cloud automation is disabled unless production mode and every explicit switch are enabled.

```text
Cursor / localhost
  -> manual one-click update
  -> local resumable worker
  -> Turso job + item progress
  -> OHLCV incremental writes
  -> latest analysis / portfolio / Top 30 refresh
```

Disabled by default:

- GitHub scheduled workflows
- GitHub push-triggered CI/CD
- Vercel Cron
- Vercel Git auto deployment
- Cloud worker API execution
- Automated email
- Automatic rollback

## Runtime switches

```env
APP_RUNTIME_MODE=development
DEVELOPMENT_MODE=true
CLOUD_AUTOMATION_ENABLED=false
VERCEL_CRON_ENABLED=false
EMAIL_AUTOMATION_ENABLED=false
GIT_DEPLOYMENT_ENABLED=false
```

Production automation requires a deliberate future release change:

```env
APP_RUNTIME_MODE=production
CLOUD_AUTOMATION_ENABLED=true
VERCEL_CRON_ENABLED=true
```

Changing environment variables alone does not restore a deleted Vercel Cron schedule. A reviewed production configuration and redeployment are still required.

## Data synchronization

1. Two-year OHLCV is the durable source of truth in Turso.
2. Daily updates are incremental by `(stock_id, trade_date)`.
3. Completed job items are skipped on resume.
4. Latest analysis is overwritten per stock rather than appended daily.
5. AI snapshots are event-based, not every-stock-every-day.
6. Update jobs can be cleaned after 30-90 days; OHLCV remains rolling two years.
