# M7.8.3 — CI/CD Deployment Stabilization

## Scope

M7.8.3 is a focused deployment repair release based on M7.8.2. It does not add stock-analysis features or another verification layer.

## Changes

- Keeps the M7.8.2 local / CI / production runtime separation.
- Pins Vercel CLI to `58.4.4` instead of using `vercel@latest`.
- Separates the Vercel Team slug from `VERCEL_ORG_ID`.
- Verifies Vercel identity and project visibility before deployment.
- Removes inherited `.vercel` state on the GitHub runner.
- Deploys source directly to the existing Production project.
- Preserves `/api/health` and `/api/ready` post-deployment gates.
- Keeps the single CI entry point: `npm run check`.

## Required GitHub Repository Secrets

- `VERCEL_TOKEN`
- `VERCEL_ORG_ID`
- `VERCEL_PROJECT_ID`

The non-secret Team slug is configured in the workflow as:

```text
caroma3689-s-projects
```

## Acceptance flow

```text
npm ci
npm run check
Vercel identity check
Vercel project access check
Production deployment
/api/health
/api/ready
```
