# M8.10.18 — Unified Status UI Binding

## Goal

Eliminate the last split-brain state where Active Job Diagnostics can show
`214 / 2143` while Development Center still renders `0 / 0`.

## Changes

- Adds `normalizeUnifiedUpdateStatus()` as the single browser-side status contract.
- Normalizes snake_case, camelCase, and nested `unifiedStatus` payloads.
- Development Center, GlobalUpdateProgress, localStorage cache, and BroadcastChannel all consume the same canonical shape.
- Status API explicitly publishes `unifiedStatus`.
- Cache key, leader lease, and BroadcastChannel namespace are versioned to M8.10.18 so old M8.10.17 `0/0` snapshots cannot overwrite current state.
- Development Center performs one bootstrap rescue read after 1.8 seconds only if the shared leader has not delivered a live status event.
- Adds a visible `UI Source / Job / processed-total` line for field diagnostics without opening the heavier Active Job diagnostics panel.
- Preserves M8.10.15+ trading-date resolution, empty-job recovery, Active Job Pointer, Queue continuation, and low Turso Rows Read design.

## Acceptance

For the same active job, these must match:

- Active Job Diagnostics processed / total
- Development Center "全市場資料"
- Development Center market percentage
- Global Update Progress
- Status API `unifiedStatus.processed_symbols / total_symbols`

No UI surface may fall back to an older cache namespace.
